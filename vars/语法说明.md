# 智绘姬 变量系统 · 语法说明

> 变量 = 存在**楼层变量**里的一份 JSON（命名空间 `st-chatu8`），结构自己定。
> 生图时在提示词里用 `$...$` 引用，插件把它**展开成 tag**；一轮结束模型再往里写新状态。
> **楼层规则**：模型读的是**上一个消息楼层**的状态，写进的是**当前楼层**（每条消息各留一份快照）。

## 一、数据长什么样

结构完全开放，插件不认键名、不要求层数。下面只是最常见的一种：多角色 × 多套服装 + 当前状态。

```json
{
  "角色列表": {
    "沈慕微": {
      "激活词": "沈慕微,沈微",
      "人物形象": "1.2::shen muwei::,long black hair,blue eyes",
      "服装列表": {
        "冷清首座蓝白渐变长袍": "blue and white robe,gold trim",
        "日常": "white shirt,black skirt"
      },
      "内部状态": { "不遍历": true, "私密标记": "hidden tag" },
      "人物状态": "$角色列表/沈慕微/服装列表/冷清首座蓝白渐变长袍$,$角色列表/沈慕微/人物形象$,smile"
    }
  }
}
```

| 字段 | 作用 |
|---|---|
| `激活词` / `key` | 门控：值里的关键词出现在正文/需求里才激活，不写＝常开 |
| `人物形象` | 角色固定形象 tag |
| `服装列表` | 多套服装，一套一个键，只存一次 |
| `人物状态` | 当前组装串：引用 + 临时 tag |
| `不遍历` | 写在对象里 = 批量调用别来拉这个块（见第六节） |
| `_` 开头 | 草稿/备注，永远不进图（显式引用也取不到） |

## 二、引用：`$路径$`

```
$沈慕微$                                 整个角色（形象 + 状态）
$沈慕微/人物状态$                         某个字段
$沈慕微/服装列表/冷清首座蓝白渐变长袍$      某套服装
$服装列表/日常$                           相对引用（写在角色内部的值里）
$/角色列表/沈慕微/人物形象$                 / 开头 = 从根算
```

- 路径分隔符 `/` 或 `.` 都行。
- 不以 `/` 开头：先按**当前节点往下**找 → 再从**根**找 → 再试 `角色` / `角色列表` / `人物` / `人物列表` 包装层。
- **展开只下探一层**：字符串 = 一项；数组 = 多项；对象 = 分组（把它的键逐个展开，键的值还是对象就不再往下）。
- **查不到就原样保留**，写错零副作用。
- `${...}$` 是预设调用（JSON 形态），不是变量；两者可以并排写在同一段。

## 三、分段与增删

```
$沈慕微/人物状态$,wet,lying                  加：引用后面直接写 tag
$沈慕微/人物状态$,-smile                    减一项 tag
$沈慕微/人物状态$,-$沈慕微/服装列表/日常$     减一整个引用产出的所有 tag
```

- 段与段用**逗号**分段；`$...$` 里面的逗号不算分段。
- `-` 只对**本段**生效，写在引用前还是后都一样；只影响这次调用，变量本身不改。

## 四、多重调用（省字写法）

一个 `$...$` 里可以写多项，用逗号 / 分号分开（半角 `,;` 和全角 `，；` 都认）。**第 2 项起接着第 1 项所在的位置继续写**：先按第 1 项的父级逐层往上找，再按第 1 项自己往下找。

```
$沈慕微/人物状态,-服装列表/冷清首座蓝白渐变长袍$,nude
   = $角色列表/沈慕微/人物状态$,-$角色列表/沈慕微/服装列表/冷清首座蓝白渐变长袍$,nude

$沈慕微/服装列表/冷清首座蓝白渐变长袍,人物形象$
   = $沈慕微/服装列表/冷清首座蓝白渐变长袍$,$沈慕微/人物形象$

$沈慕微/服装列表/冷清首座蓝白渐变长袍;人物形象$      ← 分号也行
```

- 项以 `/` 开头 = 从根算；项以 `-` 开头 = 把这**一项**展开出的 tag 从本组减掉（不是有效路径就当字面 tag 减，如 `-smile`）。
- 字面 tag 直接减：`$角色列表/沈慕微,-cold$`（减号也认全角 `－`、数学减号 `−`；带强调括号的 `{{tag}}` 一样能减）。
- **减项只减它前面已经取到的内容**（左到右）：`$沈慕微/人物状态,-服装列表,服装列表/长袍$` = 先减掉整套，再加回那一件。要减就先写减项（写在最后面就没什么可减了）。
- 花括号 `{A,B}` = 并列候选，等于把每项分别写一遍，任意层可用、可嵌套：

```
$角色列表/{沈慕微,江念}/人物状态$      多角色同字段
$沈慕微/{人物形象,服装列表/日常}$       同角色多字段
```

- 花括号里同样能写减项：`$角色列表/沈慕微/{人物状态,-服装列表/长袍}$`。
- 花括号不能紧跟 `$`（那是 `${JSON}$` 预设调用），前面要先有共同前缀。
- 写错的**路径**项直接丢掉（不会把 `服装列表/校服` 这种路径原文塞进图）；不带 `/` 的短词查不到时才当字面 tag 留着；整组都查不到 = 整个 `$...$` 原样保留。

## 五、批量调用：`*` 一级 / `**` 递归

| 写法 | 含义 |
|---|---|
| `*` | 这一层的**每个键**（一级，不往下钻） |
| `**` | 这一层往下的**所有层级**（递归拉平） |
| `人物*` | 半通配：匹配 `人物形象` `人物状态` 这类键名 |

```
$沈慕微/服装列表/*$          所有服装
$沈慕微/人物*$               人物形象 + 人物状态
$角色列表/*/人物形象$        所有角色的形象（一条搞定多角色）
$角色列表/*/人物状态$        所有角色的状态
$沈慕微/**$                  递归拉平这个角色的全部字段
$角色列表/**$                整个库递归拉平
$/角色列表/*/人物状态$        / 开头 = 从根算
```

规则：

- `*` 选中一级键后，每个键的值按老规矩展开（字符串=tag、数组=多项、对象=分组一层）。
- `**` **只收叶子**（字符串 / 数组元素），不做对象投影，因此不会重复；结果还会**自动去重**（同一个 tag 只留一次）。
- **批量调用不看激活词**：有多少拉多少，没出场的角色也会被拉出来。要保护某个块，用 `不遍历`（见第六节）。
- 永远跳过：`_` 开头的键、`激活词` / `key`、`不遍历` 标记本身。
- 一个都没命中 = 原样保留（`$沈慕微/不存在*$` 原样留在提示词里）。

可以和其他语法自由叠加：

```
$沈慕微/人物状态,-服装列表/*$,nude          用通配一次性减掉整套服装
$角色列表/{沈慕微,江念}/*$                  花括号 + 通配
```

## 六、`不遍历`：让一个块不被批量拉走

数据要留着、显式引用要用，但**批量调用（`*` / `**`）不许碰** —— 在对象里加一个保留键：

```json
"内部状态": { "不遍历": true, "私密标记": "hidden tag" }
```

- `$沈慕微/*$` / `$沈慕微/**$` → **整块跳过**（子字段也不进），不会出现 `hidden tag`。
- `$沈慕微/内部状态$` / `$沈慕微/内部状态/私密标记$` → **照样能取**（显式路径不受影响）。
- `不遍历` 这个键本身永远不产出 tag。
- 写 `false`、`"false"`、`0`、`""` = 不生效（照常被遍历）。

## 七、激活词（门控）生效范围

| 场景 | 激活词是否生效 |
|---|---|
| 整块引用 `$甲$` | ✅ 没命中就什么都不出 |
| `{{绘图激活变量}}` / `{{绘图变量视图}}` | ✅ 命中的块才出现 |
| 单字段引用 `$甲/人物状态$` | ❌ 点名了就给 |
| 批量调用 `*` / `**` | ❌ 有多少拉多少 |

## 八、宏

| 宏 | 内容 |
|---|---|
| `{{绘图变量}}` | 整份原始存储（JSON），给模型照着改，`$路径$` 指针原样保留 |
| `{{绘图激活变量}}` | 同一份结构，只保留本轮命中的块（带 `激活词`/`key` 且没命中的整块删掉） |
| `{{绘图变量视图}}` | 与 `{{绘图激活变量}}` 同义 |

宏只在插件自己的提示词管道里生效。

## 九、写入：模型输出 `<变量更新>`

```
<变量更新>
{
  "角色列表": {
    "沈慕微": { "人物状态": "$角色列表/沈慕微/服装列表/日常$,wet" }
  }
}
</变量更新>
```

- 位置：**整轮回复最末尾**（所有 `<image>` 之后）；一轮只写一次，楼内生成期间不改。
- 写进**当前楼层**：合并基准是这一楼自己的状态；这一楼还没有表时，以**上一个消息楼层**为起点。
- 只写**发生变化**的键；没变的不出现；值写空字符串 = 删除该键。
- 合并是逐层按键合并：没提到的键保持原样，对象往下合，数组/字符串整体替换。
- 值里写 `$路径$`（含多重调用、花括号、通配）= **指针原样存进变量**，等生图时才展开成 tag；写 `${ ... }$` 预设调用 = 写入时就展开成 tag 存进去。
- 这段会被插件摘掉，不进图片提示词、也不显示在聊天里；坏 JSON 整段丢弃但照样摘掉。

## 十、速查表

| 想要的效果 | 写法 |
|---|---|
| 取一个角色的组装串 | `$沈慕微/人物状态$` |
| 取某套服装 | `$沈慕微/服装列表/日常$` |
| 换装（减旧加新） | `$沈慕微/人物状态,-$沈慕微/服装列表/旧$,${JSON}$` |
| 省字换装 | `$沈慕微/人物状态,-服装列表/旧$,nude` |
| 多角色同字段 | `$角色列表/{沈慕微,江念}/人物状态$` 或 `$角色列表/*/人物状态$` |
| 一个角色全部字段 | `$沈慕微/**$` |
| 所有服装 | `$沈慕微/服装列表/*$` |
| 减掉所有服装 | `-$沈慕微/服装列表/*$` |
| 不想被批量拉走 | 对象里写 `"不遍历": true` |
| 查不到时 | 原样保留，不影响画面 |

## 十一、调试与排错

```js
window.stChatu8Vars.version        // 模块版本
window.stChatu8Vars.floor()        // 当前楼层 / 读哪一楼(上一楼) / 写哪一楼(当前)
window.stChatu8Vars.tags(楼层号)    // 指定楼层的存储
window.stChatu8Vars.rawText()      // {{绘图变量}} 的内容（读上一楼）
window.stChatu8Vars.viewText("沈慕微来了")   // {{绘图激活变量}} 的内容
window.stChatu8Vars.render("$沈慕微/人物状态$")  // 看一段提示词展开成什么（用当前楼层）
window.stChatu8VarsDebug.info()    // 状态 + 钩子统计（没有悬浮窗）
window.stChatu8VarsDebug.floor()   // 楼层去向
window.stChatu8VarsDebug.read(3) / readAll() / analyze(文本) / simulate(文本, 3) / merge(json, 3)
```

- 日志前缀 `[ChatU8 vars]`；`变量已写入楼层 N` = 写入成功。
- 设置里关掉「变量系统」开关即完全停用。
