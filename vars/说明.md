# 变量系统 使用说明

给生图 LLM 用的一套 tag 存储：多个角色、每个角色多套服装、当前形象与状态，靠引用调用。

## 一、装好之后要做的三件事

1. **开开关**：设置 → 主设置页 → 「变量系统（tag 存储）」（默认已开）。
2. **挂提示词**：把 `prompts/` 下三份文本挂到生图 LLM 能看到的地方（世界书常驻条目 / 预设里的固定段落）：
   - `变量更新规则.txt` —— 告诉模型每个字段什么时候该改
   - `变量输出格式.txt` —— 告诉模型输出格式
   - `变量结构.txt` —— 结构说明（当前值由插件自动注入，不用手填）
3. 正常生图。模型在提示词末尾多输出一段 `<变量更新>…</变量更新>`，插件自动摘掉并写进**当前这一楼**。

> **楼层怎么走**：默认是「跟随当前楼层」——模型看到的变量＝**上一个消息楼层**的状态；它这一轮改出来的结果写进**当前楼层**。
> 所以每一楼都是「那一刻的状态快照」，改哪一楼就写哪一楼（旧楼重绘也只动旧楼）。
> 设置页「变量楼层」还能切成「始终最新层」：模型看到的是**最新一楼**的状态，改出来的结果也写进**最新一楼**。
> 两种模式只在「读哪一楼、写哪一楼」上有差别，其它都一样；切模式不会动已经存好的变量。

### 两种楼层模式

设置 → 主设置页 → 「变量楼层」下拉，两种：

| 模式 | 模型读哪一楼 | 改出来的结果写哪一楼 | 什么时候用 |
|---|---|---|---|
| **跟随当前楼层**（默认） | 当前楼层的**上一楼** | **当前楼层** | 正常玩。一楼一个快照，回头改旧楼只动旧楼 |
| **始终最新层** | **最新一楼** | **最新一楼** | 想让对话一直按最新一楼的状态往下走（比如旧楼改完了，要把状态对齐到最新楼） |

- 要读的那一楼没有自己的变量表，就往前找最近一份快照（两种模式都一样）。
- 切模式只管**以后**怎么读怎么写，不会动已经存好的变量；切回默认就跟以前一模一样。

### 设置页那两个按钮

「变量楼层」下面（「最新层操作」那一行）有两个按钮，都是「立刻做一次」的意思：

- **📥 读取最新层**：马上读一遍**最新一楼**的变量，结果用冒泡提示报出来（几个角色、多少字），顺便刷新下面的「楼层状态」行。
  最新一楼自己还没有变量表时，会取**它之前最近的一份快照**，提示里也会说明是从哪一楼取的。
  什么时候用：想确认「最新一楼现在算什么状态」，或模型读到的跟你想的不一样时先看一眼。
- **📤 更新到最新层**：把**当前生效的变量状态**固化写入**最新一楼**（等于把状态对齐到最新楼）。
  如果当前楼层就是最新一楼，会退一步拿它之前最近的一份快照当来源。
  什么时候用：回去改了旧楼（或改了前面的状态），想把结果同步到最新一楼，让模型接下来按这份状态继续写。

两个按钮都只碰变量、不改聊天正文；跟上面哪种模式都不冲突，随时能点。

> 小提示：点完会有冒泡提示——读取是「最新层 12：2 个角色 / 345 字」（取值来自更早的楼层时会补一句「（取楼层 11 的快照）」），
> 更新是「已把楼层 11 的变量更新到最新层 12（2 个字段）」。

## 二、数据结构

```json
{
  "角色列表": {
    "爱莉希雅": {
      "key": "爱莉希雅,Elysia",
      "人物形象": "1.5::elysia (honkai impact 3rd)::,pink long hair,purple eyes",
      "服装列表": {
        "白色睡衣": "white nightgown,lace trim",
        "比基尼": "white bikini top,gold chain"
      },
      "人物状态": "$角色列表/爱莉希雅/服装列表/比基尼$,-gold chain,$角色列表/爱莉希雅/人物形象$,cumdrip,after sex"
    }
  }
}
```

| 字段 | 作用 |
|---|---|
| `key` | 关键词触发，逗号分隔；正文里出现任一词这个角色才参与生图。不写＝常开 |
| `人物形象` | 角色固定形象 tag（建议带同人 tag + 权重，如 `1.5::hutao (genshin impact)::`） |
| `服装列表` | 多套服装，一套只存一次 |
| `人物状态` | **当前画面的组装串**：引用 + 临时 tag。它驻留，直到被改写或淡化 |

## 三、引用语法（写在值里）

```
$爱莉希雅$                              整个角色的投影（形象 + 状态）
$角色列表/爱莉希雅/人物状态$             取某个字段
$角色列表/爱莉希雅/服装列表/比基尼$      取某套服装
$服装列表/比基尼$                       相对引用（写在角色内部的值里）
$/角色列表/爱莉希雅/人物形象$            / 开头＝从根算
```

- **不带 `$` 的字符串永远是字面 tag**，不会被当成引用。
- 找不到的路径**原样保留**，不会误删你的东西。
- **对象（`服装列表` 这类）不会自动进图**，只有被引用才展开。

### 多重调用（省字写法）

同一个 `$...$` 里可以用逗号（半角 `,` / 全角 `，` 都行，分号同理）分开写多项；**第 2 项起接着第 1 项所在的位置继续写**：先按第 1 项的父级逐层找，再按第 1 项自己往下找。

```
$沈慕微/人物状态,服装列表/冷清首座蓝白渐变长袍$        = $沈慕微/人物状态$,$沈慕微/服装列表/冷清首座蓝白渐变长袍$
$沈慕微/人物状态,-服装列表/冷清首座蓝白渐变长袍$,nude  = 旧写法 -$角色列表/沈慕微/服装列表/冷清首座蓝白渐变长袍$
```

花括号 = 并列候选，等于把每一项分别写一遍（任意层可用、可嵌套）：

```
$角色列表/{沈慕微,江念}/人物状态$                      = $角色列表/沈慕微/人物状态$,$角色列表/江念/人物状态$
$沈慕微/{人物形象,服装列表/日常}$
```

- 项以 `/` 开头 = 从根算；项以 `-` 开头 = 把这一项展开出的 tag 从这次调用里减掉（不是有效路径就当字面 tag 减，如 `-smile`）。
- 字面 tag 直接减：`$角色列表/沈慕微,-cold$`（减号也认全角 `－`、数学减号 `−`；带强调括号的 `{{tag}}` 一样能减）。
- **减项只减它前面已经取到的内容**（左到右）：所以「先减旧的、再加新的」加得回来（`$沈慕微/人物状态,-服装列表,服装列表/长袍$` = 形象 + 长袍）。
- 花括号里也能写 `-`：`$角色列表/沈慕微/{人物状态,-服装列表/长袍}$`。
- 花括号不能紧跟在 `$` 后面（那是 `${JSON}$` 预设调用），前面要先有共同前缀。
- **写错的路径项直接丢掉**（不会把中文路径原文塞进图）；整组都查不到才整组原样保留。同一内容被两项引用到时会重复，属正常。
- 两种写法完全等价：拿不准就写全路径。
### 批量调用（`*` 一级 / `**` 递归）

```
$沈慕微/服装列表/*$        所有服装（这一层的每个键）
$沈慕微/人物*$             半通配：人物形象 + 人物状态
$角色列表/*/人物状态$      所有角色的状态（一条搞定多角色）
$沈慕微/**$                递归拉平这个角色的全部字段
```

- `*` = 这一层；`**` = 这一层往下所有层级（递归，只收叶子、自动去重）。
- **批量调用不看 `激活词`**：有多少拉多少。
- 永远跳过 `_` 开头的键、`激活词`/`key`、`不遍历` 标记本身；一个都没命中就原样保留。
- 能和多重调用、花括号叠加：`$沈慕微/人物状态,-服装列表/*$,nude`。

### `不遍历`：让一个块不被批量拉走

```json
"内部状态": { "不遍历": true, "私密标记": "hidden tag" }
```

`$沈慕微/*$`、`$沈慕微/**$` 会整块跳过它（子字段也不进）；`$沈慕微/内部状态/私密标记$` 这种**显式路径照常能取**。写 `false`/`"false"`/`0`/`""` = 不生效。
### 移除语法

```
$角色列表/爱莉希雅/服装列表/比基尼$,$角色列表/爱莉希雅/人物形象$,-gold chain
```

`-tag` 对**本值里的所有引用**生效，与位置无关；只减引用结果，不动你自己写的字面 tag。

## 四、调用扩展的角色预设（可选）

```
${"name":"xiao hong","angle":"from front"}$                        只有角色特征
${"name":"xiao hong","angle":"from front","upperBody":"facial"}$   特征＋头部（不加上半身）
${"name":"xiao hong","angle":"from front","upperBody":"sfw"}$      特征＋头部＋上半身(穿)
  …再追加 "lowerBody":"sfw" / "nsfw"                             再加下半身
```

- **必须带 `angle`**，否则会被当成服装调用。
- 不写 `upperBody` ＝ 只有特征，不会带出头部。
- `upperBody` 写 `facial`（任何非 sfw/nsfw/hidden 的值）＝ 只加头部。
- 旧格式 `$xiao hong-from front-sfw-upperBody$` 也支持，但没有「只有头部」的写法。

## 五、更新格式（模型输出）

```
<变量更新>
{ "角色列表": { "爱莉希雅": { "人物状态": "$角色列表/爱莉希雅/服装列表/校服$" } } }
</变量更新>
```

- 写进**当前楼层**——默认（跟随当前楼层）就写当前楼层；切到「始终最新层」时写**最新一楼**（见第一节）。合并基准是这一楼自己的状态；这一楼还没有表时以**上一楼**为起点。
- 值里写 `$路径$`（含多重调用、花括号、通配）= **指针原样存进变量**，生图时才展开成 tag；写 `${ ... }$` 预设调用 = 写入时就展开成 tag 存进去。
- 只写变化的部分；**空字符串 = 删除该字段**；对象 = 往库里加条目。
- 这段会被插件从提示词里摘掉，不会进图片提示词，也不会显示在聊天里。
- 坏 JSON：整段丢弃、不写变量，但照样摘掉（保证画面不被污染）。

## 六、存在哪

写在**消息楼层变量**里，命名空间 `st-chatu8`：`chat[i].variables[swipe_id]["st-chatu8"]`。

- 跟聊天文件走；删楼 / swipe 自动隔离；不会碰 MVU 的 `stat_data`。
- **读**（跟随当前楼层，默认）：给模型看的变量取「上一个消息楼层」（这一楼还没有就从更早的楼层往前找最近一份）。
- **读**（始终最新层）：给模型看的变量永远取「最新一楼」的变量表；它自己还没有就往前找最近一份快照。
- **写**（跟随当前楼层）：更新写进「当前楼层」（正在处理的那条消息）。
- **写**（始终最新层）：更新一律写进「最新一楼」，不管正在处理哪一楼；设置页「📤 更新到最新层」也是写这一楼。
- 生图求值 `$路径$` 用**当前要写的那一楼**的状态：跟随模式＝当前楼层，最新层模式＝最新一楼。

## 七、排错

- F12 控制台输入 `window.stChatu8Vars` 应有对象；`window.stChatu8Vars.tags()` 看当前存储。
- 控制台调试接口 `window.stChatu8VarsDebug`（**没有悬浮窗**，都在 F12 控制台里用）：
  `info()` 状态与钩子统计 · `floor()` 当前楼层/读哪一楼/写哪一楼 + **当前模式**（`mode` 字段，`"follow"` 或 `"latest"`） · `read(id)` / `readAll()` 读楼层变量 ·
  `analyze(文本)` 只看解析 · `simulate(文本, id)` 按真实流程跑一遍 · `merge(json, id)` / `write(json, id, "replace")` 写入 · `clear(id)` 清空 ·
  `setMode("follow"|"latest")` 切楼层模式（跟设置页那个下拉一样）· `readLatest()` 读最新层 · `commitLatest(fromId)` 把当前状态固化到最新层。
- 设置页「楼层状态」那一行就是这四个信息：`当前楼层 12 · 读取 11 · 写 12 · 模式 跟随当前楼层`（切到最新层模式时显示「模式 始终最新层」）。
  读/写楼层跟预期不一样时，先看这一行，再用 `floor()` 核对具体是哪几楼。
- 插件日志前缀 `[ChatU8 vars]`；`ChatU8: 变量块已解析并写回楼层 N` 表示写入成功。
- 设置里关掉「变量系统」开关即完全停用（`render` 不再替换、更新块不再解析）。
